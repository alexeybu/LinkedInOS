# Claude LinkedInOS

A Claude Code workspace for running a LinkedIn content strategy: capturing your writing voice,
turning real work into post ideas, drafting posts that read as human-written, and tracking what
actually performs. Built as a sibling to [JobOS](../JobOS/CLAUDE.md) — same conventions, same
`.claude/skills/` pattern — because the end goal is the same: visibility to recruiters/HRs during
the job search, not generic personal branding.

## Layout

- `voice/style-profile.md` — the single source-of-truth writing-voice profile (tone, rhythm,
  vocabulary, formatting habits, things you'd never say). Every drafting skill reads this. Never
  invent voice traits that aren't backed by real samples or explicit user input.
- `strategy/content-pillars.md` — the 3-4 topics you post about and why, plus target audience and
  goals (SSI, profile views, reachouts).
- `strategy/calendar.md` — what's queued/posted, pillar balance over time, cadence.
- `ideas/backlog.md` — post concepts, tagged by pillar, sourced from real work/experience.
- `drafts/` — one file per in-progress post: `drafts/<date>-<slug>.md`. Safe to regenerate/discard.
- `drafts/images/` — one PNG per drafted post that has a card image, named to match its draft
  (`drafts/images/<date>-<slug>.png`), generated by `post-image`. The draft's frontmatter points
  to its image via an `image:` field.
- `published/performance-log.md` — manually-entered stats per post after it goes out (LinkedIn has
  no public API for this — you paste numbers in).
- `templates/` — reusable hook formulas and post-structure templates.

## Skills

`.claude/skills/` is being built one skill at a time:

- `voice-profile` — builds/updates `voice/style-profile.md`, either from writing samples you
  provide (past LinkedIn posts, emails, Slack) or via an interview if no samples exist. Run this
  first, and re-run whenever your voice profile feels stale or drifts.
- `content-strategy` — defines/updates content pillars, audience, cadence, and goals in
  `strategy/content-pillars.md`. Checks memory for recruiter/HR target-role info (e.g. surfaced
  from a prior JobOS session) instead of reading JobOS files directly — LinkedInOS is a standalone
  skillset and doesn't assume any sibling project is present.
- `trend-scan` — web-research pass on current LinkedIn format/topic trends and named-creator
  patterns in the user's space, plus gap-hunting against the current pillar list. Writes
  `strategy/trend-notes.md`. Re-run periodically (trends move fast); not needed on every
  `idea-mine` run.
- `idea-mine` — mines real material (memory, `strategy/trend-notes.md` if present, live
  conversation, or content the user pastes/points to explicitly for that run) into pillar-tagged
  post ideas in `ideas/backlog.md`. Doesn't read from sibling projects (JobOS or otherwise) by
  default. Never sources ideas from LinkedInOS/JobOS itself — that's explicitly off-limits per
  `strategy/content-pillars.md`.
- `draft-post` — takes one idea from `ideas/backlog.md`, writes 2-3 hook variants + a full post in
  your voice, respecting LinkedIn's real mechanics (length, hook cutoff, no in-body links) and a
  dialed-down, modest take on "viral" structure. Runs an inline authenticity check (its own
  self-contained logic, standing in for `humanize-check` until that exists separately) and writes
  `drafts/<date>-<slug>.md`.
- `humanize-check` *(not yet built as a standalone skill — its logic currently lives inline inside
  `draft-post`)* — will eventually lint any draft against common AI writing tells and against
  `voice/style-profile.md`, callable standalone.
- `post-image` — generates a dark quote-card PNG for a drafted post (`drafts/images/<slug>.png`):
  a serif hook quote, a small broken-ring "gap" motif, a pillar kicker, a closing tagline.
  Rectangular (1080x608) by default; matches the same modest, no-stock-photo calibration as the
  post text itself.
- `content-calendar` *(not yet built)* — maintains `strategy/calendar.md`.
- `log-performance` *(not yet built)* — appends pasted-in post stats to
  `published/performance-log.md`.
- `review-performance` *(not yet built)* — reads the performance log, reports what's working
  (pillar/format/hook/timing), feeds findings back into `content-strategy` and `idea-mine`.
- `cleanup-strategy` — resets `strategy/content-pillars.md`, `strategy/trend-notes.md`, and
  `ideas/backlog.md` back to placeholder/empty, backing everything up first. Never touches
  `voice/style-profile.md`. Use to re-run `content-strategy`/`trend-scan`/`idea-mine` cleanly.

## Workflow

1. Run `voice-profile` once to establish your writing voice; re-run when it needs updating.
2. Run `content-strategy` once to set pillars/audience/cadence/goals; revisit periodically.
3. Run `trend-scan` occasionally (e.g. monthly) to refresh `strategy/trend-notes.md` with current
   LinkedIn format/topic trends and gap candidates.
4. Run `idea-mine` to keep `ideas/backlog.md` stocked with real, specific post concepts, informed
   by trend notes when available.
5. Pick an idea, run `draft-post` to get a polished, voice-matched draft.
6. Post it yourself on LinkedIn — this workspace never publishes on your behalf.
7. Run `log-performance` once you have stats to paste in.
8. Periodically run `review-performance` to see what's working and adjust pillars/ideas
   accordingly.

## Ground rules

- Never fabricate accomplishments, numbers, or stories — post content must trace back to real
  experience: your own account (live conversation), memory, or content you explicitly paste/point
  to for that run. LinkedInOS doesn't read from JobOS or other sibling projects by default.
- Never auto-post or otherwise publish to LinkedIn programmatically — this workspace only prepares
  drafts. Publishing LinkedIn automation also risks the account (LinkedIn ToS), independent of any
  Claude Code policy.
- `voice/style-profile.md` should only encode traits backed by real samples or something you
  actually said — don't let it drift toward generic "punchy LinkedIn voice."
